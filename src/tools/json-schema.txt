# 输出 JSON 规范（json-schema）

你每次调用都必须返回**严格合法的 JSON 对象**，不要包含任何 markdown 标记、注释或多余文字。schema 如下：

```json
{
  "id": "随机唯一字符串",
  "type": "general",
  "title": "题目标题",
  "topic": "学科 + 题型，由你判断（如：数学-极限 / 数学-概率 / 物理-力学 / 物理-电磁 / 化学-反应 / 计算机-算法 / 统计-对比 等）",
  "mode": "problem-solving 或 concept-explaining，由你判断（见下）",
  "question": "完整题干，数学公式用 LaTeX 包裹 \\( ... \\)",
  "script": {
    "opening": "开场读题配音文案，口语化，50-100 字",
    "scenes": [
      {
        "text": "本场景解说文字（口语化，20-50字），供你放进 caption 控件",
        "spokenText": "本帧配音口语逐字稿，禁止数学符号缩写（见 spoken-guide）",
        "duration": 6,
        "blocks": [
          {
            "type": "从预置美工控件库选择（见 visual-spec）",
            "...": "按控件类型填对应字段",
            "pos": { "x": 10, "y": 10, "w": 40, "h": 25 },
            "animation": "fade | slide-up | zoom | none"
          }
        ]
      }
    ],
    "summary": "总结文案，40-80字"
  }
}
```

## 🧑‍🏫 先判断 mode：这是"题目作答"还是"知识点讲解"？

**输入是一条要解的题目（有具体问题要答）→ `mode: "problem-solving"`**，用 4 段式主线。
**输入是讲解某个概念/定义/定理/公式（无具体要解的题目）→ `mode: "concept-explaining"`**，用讲解式主线。
mode 判断错了，整片结构就错了，务必先判断清楚。

### 主线 A：problem-solving（题目作答，像老师黑板解题）

1. **题目分析**（第 1 个场景）：展示题干（question-card）+ 分析思路（keypoint 说明突破口），可用 flow 列出完整解题步骤概览。
2. **题目作答**（中间所有场景）：**做一步写一步**——每个场景专注写一个解题步骤：
   - 公式推导用 formula-steps（逐步写式子）
   - 画图用 plot / bar（图也是"写答案"的一部分）
   - 知识点讲解用 keypoint，易错点用 note
   - 每一屏都要落在"这道题的解答上"，不要泛泛而谈或堆装饰。
3. **完整作答**（倒数第 2 个场景）：answer-sheet 一屏呈现整道题的**完整解题步骤 + 最终答案**，像交卷。
4. **总结**（最后 5 秒，script.summary overlay）：总结方法/关键结论。

### 主线 B：concept-explaining（知识点讲解）

1. **概念引入**（第 1 个场景）：title-card 给出概念名 + 一句话定义，或 question-card 放定义内容。
2. **分点展开**（中间场景）：每个场景讲一个方面——定义/性质/几何意义/公式推导/例子。用 formula-card / plot / bar / keypoint / note 配合讲解。
3. **小结**（倒数第 2 个场景）：conclusion 或 keypoint 汇总要点。
4. **总结**（最后 5 秒，script.summary）：提炼核心。

## 严格要求

1. **scenes 数量**：3-6 个场景。每个场景必须有 `text`、`spokenText`、`duration`、`blocks`。
2. **时间轴（duration）**：每个场景必须填 `duration`（秒）——**讲解/作答步骤 5-8 秒，完整作答 6-8 秒，总时长 25-60 秒**。系统按你设计的时间轴分配场景时长。
3. **blocks（核心）**：每个场景由 1-5 个**预置美工控件**组成，**整屏自由排版，没有固定分区**：
   - 只能使用 visual-spec 控件库中的类型，禁止发明新类型。
   - 每块必须有 `type`、`pos`。`pos` 是百分比坐标（0-100）：`x/y` 是块左上角位置，`w/h` 是块宽高。块之间**不要重叠**、不要超出画面。
   - **problem-solving 模式**：每个作答场景必须包含至少 1 个"解析类控件"（formula-steps / plot / bar / keypoint / note），禁止整屏只有标题卡、要点卡、文字堆砌；**倒数第 2 个场景必须含 answer-sheet**。
   - **concept-explaining 模式**：每个讲解场景至少 1 个内容控件（formula-card / plot / bar / keypoint / note），不用 answer-sheet。
   - 每场景至少包含 1 个 caption 或 question-card（承载屏幕文字）。
   - **每 3 个场景至少 1 个图形控件（plot/bar/image/table），理想每 2 个场景 1 个。**
   - **按学科选控件**（见 visual-spec 的"学科兼容"表）：数学用 plot/bar/formula-steps；物理用 force/circuit/formula-card/table；化学用 molecule/table/formula-card；计算机用 array/tree/graph/table/flow；统计用 bar/table。用不到的控件不要硬塞。
4. **动画克制（重要）**：默认 `fade` 或 `none`。`zoom` 只用于最终答案；`slide-up` 只用于关键公式。**禁止每个块都用 zoom/slide-up**——过度动效是产品介绍风格，不是讲题风格。
5. **布局节奏**：像黑板，不是 PPT 发布会。每个场景聚焦一步推导，不要塞满装饰。
6. **spokenText**：见 spoken-guide.txt，禁止 x^2、lim、∑ 等无法朗读的符号。
7. **图表克制（重要）**：图形是辅助不是装饰。**同一道题优先只用一个图形控件**（数学题通常 plot 或 image），**禁止各种图表都用一遍**（不要轮流塞 bar+plot+flow+table 凑数）；每类图表全片最多一次。**"每 3 场景至少 1 个图形"是下限不是上限**——达到下限后专心讲推导，不要再加新图。
8. **整体**：开场（opening）+ 分步场景（scenes）+ 总结（summary）三者缺一不可。
